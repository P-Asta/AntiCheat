## 스태미나: 확정 감지를 추가하지 않은 이유

BetterStamina 1.0.2는 소유 클라이언트의 `LateUpdate` 전후 게이지 차이를 수정합니다. 소모 0.75배·회복 1.25배, 계산 중 무게 0.5배를 적용한 뒤 무게를 복원하며 점프 소모도 0.75배로 조정합니다. 호스트에 설치 목록이나 변경한 게이지를 보내는 식별 프로토콜은 없습니다.

게임의 `sprintMeter`는 일반 필드입니다. 실제 소모·회복은 소유 플레이어에서만 계산하며 위치·애니메이션·탈진 상태 전송에 실제 게이지가 포함되지 않습니다. 호스트의 원격 `sprintMeter`나 `isSprinting`을 실제 상태로 사용해서는 안 됩니다.

정상 예외도 있습니다.

- TZP는 사용 중 직접 회복을 추가하고 `drunkness` 곡선으로 소모·회복을 변경합니다. 사용을 멈춘 후에도 잔류 효과가 남습니다.
- 사망/새로운 중상 분기가 아닌 정상 피해 경로에서 10 이상 피해는 `damage / 125`만큼 게이지를 회복합니다(최대 1). 예를 들어 10 피해는 8%입니다. 모든 체력 감소에 일괄 적용되는 것은 아닙니다.
- 정상 점프·이동 방해·걷기/정지·아이템 무게도 계산에 관여합니다.

따라서 단순한 질주 지속 시간 기준이나 원격 게이지 정지 기준으로 자동 차단·강퇴하지 않습니다. 이 릴리스는 BetterStamina 차단을 보장하지 않으며, 클라이언트 자기보고를 추가하는 것만으로도 변조 방지를 보장할 수 없습니다.

## 1.0.2: 호스트 전용 반복 질주 의심 관찰

확정 감지 대신 호스트가 이미 받는 위치·애니메이션을 읽는 관찰 기능입니다. `PlayerControllerB.LateUpdate`에서 호스트의 원격 플레이어만 0.25초 간격으로 관찰하며, 시간 간격은 게임의 scaled time을 사용합니다. 위치는 안정적인 부모 기준의 `serverPlayerPosition`, 질주 상태는 원격 Animator의 `Sprinting` 태그를 사용합니다. 원격 `sprintMeter`와 `isSprinting`을 근거로 사용하지 않습니다.

### 후보 확인과 알림

1. 처음 관찰하거나 불확실한 상태에서 복구한 뒤 안전한 비질주 상태가 2초 유지되어야 새 구간을 시작합니다.
2. 한 구간에서 질주 시간이 `2 × sprintTime`을 넘고 누적 수평 이동 거리도 `2 × sprintTime × movementSpeed × 2.25`를 넘어야 후보가 됩니다. 실행 중 게임 값을 사용하며, 무게는 가장 관대한 값인 1로 가정합니다.
3. 질주를 멈춘 뒤 안전한 휴식이 2초 유지되어야 후보를 확인합니다. 그 사이 도착한 피해·TZP 정보가 있으면 후보와 이전 근거를 모두 지웁니다. 연속 질주 한 번에서는 후보를 하나만 만듭니다.
4. 이렇게 확인한 독립 구간이 300초 안에 3회 모이면 호스트 로컬 채팅으로 의심 알림을 표시합니다. 알림 후 120초 동안 다시 알리지 않고, 다음 알림에도 새로운 근거가 필요합니다.

`[StaminaObservationSetting] Enable=true`가 기본값이며 강퇴 옵션은 없습니다. `[DetectedMessageType]`이 `GUI`나 `PublicChat`이어도 이 관찰 알림은 호스트의 로컬 채팅만 사용합니다. `RpcGuard`나 `KickPlayer`를 호출하지 않고, 이동·스태미나·체력 상태를 변경하거나 RPC 요청을 차단하지 않습니다. 기존의 비정상 요청 차단과 별개입니다.

### 제외와 초기화

다음 상태에서는 현재 후보뿐 아니라 누적 근거도 초기화합니다.

- TZP 사용·잔류 효과·약품 소지, 피해 이벤트나 피해 시각 변화, 체력 변화 또는 만피가 아닌 상태. 피해·TZP 이후에는 `max(10초, 2 × sprintTime)` 동안 추가 유예합니다.
- 순간이동·비현실적인 위치 변화, 차량·사다리·physics parent·특수 애니메이션·제트팩·미끄러짐·외부 이동 영향.
- 질주 중 오래된 위치 정보, 0.75초를 넘는 관찰 공백, 역행하는 시간·timescale 변경, 실행 중 이동 관련 값 변경, NaN/무한대·누락된 상태.
- 부모·플레이어 식별·라운드 상태 변경. 접속 종료와 수명 종료 시에도 관찰을 정리합니다.

위치 갱신이 없는 정상 정지 상태는 안전한 휴식으로 인정할 수 있지만, 갱신이 없는 질주 상태는 근거로 쌓지 않습니다. 제외 조건이 끝났다는 이유만으로 즉시 관찰을 재개하지 않고 안전한 2초 휴식을 다시 요구합니다.

### 해석의 한계

시간·거리 배수와 반복 횟수는 보수적인 **진단용 추정치**이며 정상 플레이의 수학적 상한이나 치트 증명이 아닙니다. 호스트가 받은 정보만으로 클라이언트에 정상 효과가 없다는 사실을 확정할 수 없고, 특정 BetterStamina 설치를 알아내지도 못합니다. 오탐이 없다고 보장할 수 없으므로 알림만 제공합니다.

작은 소모 변경, 회복 속도만 바꾸는 기능, 무거운 짐을 든 플레이어는 기준을 넘지 않을 수 있습니다. 쉬지 않는 단일 무한 질주도 3개의 독립 구간으로 중복 계산하지 않으므로 알리지 않을 수 있습니다. 의심 알림이 없다는 사실도 정상 플레이의 증명은 아닙니다.

## 호환성과 범위

설치 DLL에서 기존 명시 Harmony 대상 90개 중 5개가 없어 선택적 구형 패치로 옮겼습니다. EnemyAI 위치, 플레이어 전체 아이템 버리기·사망·위치, GrabbableObject 활성화의 구형 RPC입니다. 없는 대상은 경고 후 건너뛰며 다른 패치의 등록을 계속합니다. 새 universal RPC는 송신자와 중계 방식이 다르므로 번호만 교체하지 않았습니다. 이 5개 구형 검사는 해당 대상이 없는 버전에서는 동작하지 않습니다.

SkidPwner처럼 모든 클라이언트의 구매·집기를 금지하지 않습니다. LobbyGuard의 NGO batch/hash/transport 및 Dissonance 음성 검증 전체도 포함하지 않습니다. 최신 위치 RPC는 호스트 handler 차단만으로 다른 관찰자에게 가는 중계를 막을 수 없고 wire sender를 인증된 sender로 간주할 수 없어, 이 방식의 이동 제재를 추가하지 않았습니다.

## 검증 방법

이전 1.0.1 실행: 획득54 + 구버전 슬롯38 + 가방28 + 거래112 + 채팅50 + 알림16 + 실제 Harmony 호환성6 = 304회, 실패0. 호환성 검사는 구형 대상 없음/전부/일부의 각2개 검사입니다. 당시 Release 빌드 오류0, NU1603/Harmony003 경고75. 독립 코드 검토에서 발견한 기존 강퇴 설정 우회와 packed 정수 인코딩 문제, 무료상품 할인 절삭 문제를 회귀 테스트로 재현 후 수정했습니다.

1.0.2 최종 재실행: 획득54 + 구버전 슬롯38 + 가방28 + 거래112 + 채팅50 + 알림21 + 구형 Harmony 호환성6 + 질주 추적기43 + 호스트 연결부44 + 실제 Harmony 관찰 패치15 = **411회 통과, 실패0**. 새 관찰 패치의 실제 Harmony 검사는 선택적 이벤트 전부/일부/없음에서 각각9/4/2회로, 원본 메서드 실행·누적 근거 초기화·관찰 재개를 확인했습니다. Release 빌드 오류0, 기존 NU1603/Harmony003 경고75입니다.

독립 검토에서 같은 플레이어의 부모 좌표계 변경이 알림 대기시간을 없애는 문제가 발견되어 실패를 재현한 뒤 수정했습니다. 미세 timescale 변경과 원격 미끄러짐 신호도 회귀 테스트로 보완했습니다. 원격 순간이동 플래그가 남는 원본 동작은 플래그 상승 엣지와 실제 순간이동 이벤트로 처리하며, 게임 필드를 변경하지 않습니다. 최종 검토의 미해결 중요 지적은 없습니다.

회귀 실행은 실제 production prefix·알림·선택적 대상 선택 코드를 링크하고 Unity/NGO 외부 경계를 대체합니다. 잘못된 입력이 기존 코드에서 실패하는 RED를 확인한 다음 수정했습니다. packed 정수 codec 자체, 실제 Harmony 전체 로딩 및 멀티플레이는 별도 검증 대상입니다. Release 빌드는 설치 게임과 동일 계열의 캐시된 v81 API 참조를 사용합니다.

게임에서 확인할 항목: 두 플레이어의 정상 구매/무료 상품/보증 교환/행성 이동, GUI·호스트 채팅·공개 채팅 알림, 정상 50자 채팅, 호환성 경고와 나머지 패치 로딩. 질주 관찰은 정상 질주·무거운 짐·TZP 사용과 잔류·피해 후 질주·차량·순간이동·라운드 전환·재접속에서 오탐이 없는지, `PublicChat` 설정에서도 알림을 호스트만 보는지 별도로 확인해야 합니다. 실게임이나 공개 방에서 새 관찰 기능을 검증하지 않았습니다.
